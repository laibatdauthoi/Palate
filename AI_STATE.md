# Decisions Made During Development

- Preserve the approved Home composition as the visual reference; scale work should adapt around it rather than redesign it.
- Keep layout scale rollout staged and documented through [`docs/Layout_scale_rules.md`](./docs/Layout_scale_rules.md).
- Avoid touching Challenge / Settle sizing or behavior casually; those selectors have already had regression history.
- Keep filter/tab pill styling distinct from primary action button styling.
- Prefer migrating shared/generic selectors first: compact buttons, filter shells, modal shell spacing, utility notes, and claim toggles.
- Apply text scaling through clamped shared tokens and pair it with explicit overflow rules instead of letting text scale or wrap implicitly.
- Treat controller/runtime variables and visible selector consumption as separate checks; a healthy controller alone does not guarantee visible scaling.
- When sidebar width changes, recalibrate shell guttering first instead of compensating by inflating page internals, cards, or buttons.
- Application Layout is now the explicit owner of viewport shell, sidebar/content relationship, layout-mode switching, content frame width/padding, and shell-level scroll behavior.
- For responsive cleanup, keep media-query boundaries stable first and add ownership markers in place; do not move Home selectors across mixed blocks until the remaining composition bridges to FilterBar, WaitingPushCard, and MatchCard are isolated.
- For Home cleanup, preserving computed layout parity took priority over removing every ownership leak; documented legacy exceptions are preferred over risky selector moves.
- For FilterBar/Tabs cleanup, reusable shell behavior should move behind component-owned variables first; the new `--tab-button-flex` hook follows that rule and preserves computed output.
- When a route still needs special FilterBar/Tabs shell behavior, prefer route-scoped variables on the FilterBar placement selector over descendant overrides into `.tabs` or `.tab_button`.
- Do not migrate card-size selectors, Home composition offsets, or match/waiting card internals blindly; document them as skipped when they are risky.
- Treat `--action-button-*`, `--card-footer-*`, `--card-actions-*`, `--filter-bar-*`, and `--tab-button-flex` as durable component contract families.
- Treat `--waiting-push-*`, `--match-card-*`, `--claim-row-*`, `--activity-row-*`, and `--activity-header-actions-*` as temporary bridge families that must not be expanded casually.
- Treat `--waiting-push-*` specifically as WaitingPushCard family-owned bridge hooks, not as reusable Card Foundation variables.
- Treat `--match-card-*` specifically as MatchCard family-owned bridge hooks, not as reusable Card Foundation variables.
- Treat `--claim-row-*`, `--activity-row-*`, and `--activity-header-actions-*` specifically as Claim / Activity family-owned bridge hooks, not as reusable shared ActionRow or Card Foundation variables.
- Do not replace selector complexity with variable complexity; if a new variable only preserves one local exception, document it as a bridge hook rather than treating it as a permanent shared contract.
- CSS file splitting must happen only after ownership is stable; moving selectors early would relocate mixed ownership instead of fixing it.
- First CSS extraction should stay limited to durable shared owners; protected card-main, match-footer, and route CTA button selectors remain in [`frontend/styles/globals.css`](./frontend/styles/globals.css) until their family/page contracts are extracted separately.
- Shared FilterBar/Tabs contract rules can move into [`frontend/styles/filter-bar.css`](./frontend/styles/filter-bar.css), but Home placement selectors and route-scoped FilterBar variable assignments must remain in [`frontend/styles/globals.css`](./frontend/styles/globals.css) until page-composition extraction.
- Shared Badge / MediaTag contract rules can move into [`frontend/styles/badges.css`](./frontend/styles/badges.css), but MatchCard decorative tag placement, card-family badge overrides, and page-specific badge placement must remain in [`frontend/styles/globals.css`](./frontend/styles/globals.css) until card/page extraction.
- Shared Card Foundation rules can move into [`frontend/styles/cards.css`](./frontend/styles/cards.css), but WaitingPushCard, MatchCard, Claim/Activity families, page grid/composition selectors, and protected transaction-control paths must remain in [`frontend/styles/globals.css`](./frontend/styles/globals.css) until their later extraction phases.
- Shared WalletPanel rules can move into [`frontend/styles/wallet.css`](./frontend/styles/wallet.css), but navigation/sidebar shell ownership, page/layout placement, and mixed shell cleanup blocks must remain in [`frontend/styles/globals.css`](./frontend/styles/globals.css) until navigation/layout extraction.
- Shared Navigation/sidebar rules can move into [`frontend/styles/navigation.css`](./frontend/styles/navigation.css), but app shell, layout-mode visibility/rail/mobile behavior, page/layout placement, and mixed cleanup blocks must remain in [`frontend/styles/globals.css`](./frontend/styles/globals.css) until shell/layout extraction.
- Shared application layout rules can move into [`frontend/styles/layout.css`](./frontend/styles/layout.css), but Home composition selectors, page-specific layout exceptions, `mobile_bottom_nav`, and mixed shell+page blocks must remain in [`frontend/styles/globals.css`](./frontend/styles/globals.css) until later page cleanup.
- Buff Find Match should block obvious no-match wallet popups in the frontend, but still allow real contract-side errors to surface when the frontend cannot know better.
- Treat these AI handoff files as canonical context and update them when architecture or current work state materially changes.
