# Frontend Rules

Use Next.js with TypeScript.

Use App Router.

Do not add a backend database.

Frontend data should come from:
the current execution layer for game data
Shelby for media data

All user-facing product text must use the name Palate.

Before implementing UI, read:
docs/Palate_spec.md
docs/Palate_ui_spec.md
docs/design_tokens.md
docs/Shelby_notes.md
docs/Codex_rules.md

Do not invent a generic crypto dashboard UI.

Do not make the UI look childish or overly cute.

Do not use bright candy pink.

Do not expose live active match score, active love pool, active leading side, or active win probability.

Judge page must feel dramatic and focused.

My Media must clearly show media status and available action.

Waiting Pushes must feel competitive.

Claims and Profile must feel clean and readable.

Prefer reusable components.

Use a design system approach with shared tokens, shared button styles, shared card styles, and shared badges.

If styling decisions are unclear, prefer premium dark GameFi elegance over loud Web3 clichés.
